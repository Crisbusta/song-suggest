# Rediseño de la vista Sortear (v2) — plan de implementación

> **Para el agente que lo ejecute:** lee primero `AGENTS.md` en la raíz (es un
> enlace simbólico a `CLAUDE.md`): trae las convenciones del repo y las zonas que
> no se tocan. Este plan se ejecuta **tarea por tarea**, en orden. Cada una
> termina con algo verificable y su propio commit. Los pasos usan casillas
> (`- [ ]`) para llevar la cuenta.

**Objetivo:** rediseñar la vista Sortear — lista de pistas siempre visible,
panel del amplificador permanente, controles en una sola barra — y partir
`public/app.js` (1.362 líneas) en módulos mientras se hace.

**Arquitectura:** sólo cambia la capa de presentación. El servidor, `db/` y
`lib/` **no se tocan**: la API ya devuelve todo lo necesario. `public/app.js` se
reduce a arranque y conmutación de vistas; la vista Sortear y el panel del
amplificador salen a módulos propios; toda la lógica que pueda ser pura va a
`public/tarjeta.js`, que es el único módulo del front con tests.

**Stack:** Node ≥ 24. JavaScript vainilla, **cero dependencias de npm**, sin paso
de build. Módulos ES servidos tal cual desde `public/`. Tests con `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-12-rediseno-v2-design.md` — léela
entera antes de empezar. El plan argumenta desde ella; ante una contradicción,
manda la spec.

**Referencia visual:** `docs/mock-v2.html`. Es un bundle de React de 436 KB:
**se mira, no se copia ni se adapta.** Para verlo, sírvelo por HTTP (el
protocolo `file:` suele estar bloqueado).

## Restricciones globales

- **Cero dependencias de npm en tiempo de ejecución.** La única dependencia nueva
  permitida en todo el plan es `@playwright/test` como `devDependency`, y sólo en
  la Tarea 7.
- **No modificar** `public/fender-protocolo.js`, `public/despachador.js` ni
  `public/ampli-usb.js`. Son el transporte al amplificador, verificado contra el
  equipo real. El rediseño cambia *qué* se le pasa, nunca *cómo* se manda.
- **No modificar** `db/`, `lib/`, `server.js` ni `etl/`. Si crees que necesitas
  tocarlos, párate y repórtalo: significa que el plan está mal.
- **`song_state` no se toca.**
- Comentarios en español **sin tildes dentro de `.js`**. El Markdown sí las lleva.
- **Nunca inventar un dato.** Si la fuente no lo trae, viaja `null` y la interfaz
  no lo dibuja.
- `esc()` sobre cualquier texto del catálogo que llegue a HTML. Los nombres de
  pista y de artista son texto de terceros.
- Los 355 tests existentes deben seguir verdes en todo momento.

## La forma de los datos (verificada el 2026-09-12)

`/api/roll`, `/api/song` y `/api/lists` devuelven canciones con esta forma exacta:

```js
song = {
  songId, artist, title,
  pistas: [ /* todas las de guitarra, ordenadas por views desc */ ],
  pistaPorDefecto,   // indice dentro de `pistas`
  tags,              // string[]
  officialVideo, backingVideo, url, liked
}

pista = {
  trackIndex,   // indice en la tabla `tracks`, NO la posicion en el arreglo
  instrument,   // "Distortion Guitar", "Acoustic Guitar (steel)", ...
  name,         // crudo del catalogo, puede ser null o ''
  difficulty,   // 1..10
  tuning,       // string ya legible, o NULL si es afinacion estandar
  califica,     // bool: cumple el filtro con el que se sorteo
  ampli,        // null, o el objeto de abajo
}

ampli = {
  modelo, fenderId, gain, volume, treble, bass, mid, reverb,
  cadena,       // OJO: solo trae las ranuras USADAS. Las vacias NO vienen.
  fuente,       // 'comunidad' | otra
  incierto,     // bool: la planilla marco este preset como dudoso
  procedencia, motivos, paraElAmpli
}
```

**Dos trampas que el plan te ahorra:**

1. **`tuning: null` significa afinación estándar**, no "desconocida". Hoy la
   interfaz no dibuja nada en ese caso. El rediseño muestra `E estándar`.
2. **`cadena` sólo trae las ranuras usadas.** Para dibujar las cinco
   (`stomp`, `mod`, `amp`, `delay`, `reverb`) usa la constante `RANURAS` de
   `public/catalogo-lt25.js` y marca como `vacía` la que no esté en `cadena`.

- [ ] **Paso 3: implementar**

Al final de `public/tarjeta.js`:

```js
/* Palabras que delatan el ROL de una pista, que es lo que un guitarrista
   necesita para elegir. No es una lista de instrumentos: es lo que distingue
   una pista de sus hermanas en la misma cancion. */
const ROLES = /\b(lead|rhythm|solo|clean|acoustic|electric|harmon|extra|overdub|intro|outro|slide|fingerstyle|nylon|steel|riff|melody|arpegg|chord)/i

const segmentos = nombre =>
  String(nombre ?? '').split('|').map(s => s.trim()).filter(Boolean)

/* La etiqueta corta de cada pista de UNA cancion.

   Recibe todas a la vez a proposito: dos de los tres pasos son por cancion.

   El catalogo NO tiene un orden fijo de segmentos. En Fade to Black es
   "Musico | Equipo | Rol"; en Tears In Heaven es "Musico | Rol | Equipo". Por
   eso la regla obvia -- quedarse con el ultimo -- deja las cuatro pistas de
   Clapton llamadas "C.F. Martin 000-42". Medido sobre las 25.061 pistas reales:
   el ultimo segmento colisiona en el 10,1% de las canciones; estos tres pasos
   dan 0%, con 15,8 caracteres de media.

   El nombre crudo completo NO se pierde: quien dibuje esto lo pone en el
   `title` del elemento. */
export function etiquetasDePistas(pistas) {
  const listas = pistas.map(p => segmentos(p.name))

  // 1. Fuera lo que se repite en TODAS: el musico, el modelo de guitarra.
  // 2. De lo que queda, el segmento que nombra un rol; si no, el ultimo.
  let base = pistas.map((p, i) => {
    const s = listas[i]
    if (!s.length) return p.instrument
    const comunes = pistas.length > 1
      ? new Set(s.filter(x => listas.every(l => l.includes(x))))
      : new Set()
    const quedan = s.filter(x => !comunes.has(x))
    const b = quedan.length ? quedan : s
    return b.find(x => ROLES.test(x)) ?? b[b.length - 1]
  })

  /* 3. Desempate: contra LA HERMANA con la que choca -- no contra todas -- el
     primer segmento que ella no tiene. Es lo que separa "1st Guitar" de
     "2nd Guitar" en Tears In Heaven. */
  base = base.map((e, i) => {
    const chocan = base.map((o, j) => (j !== i && o === e ? j : -1)).filter(j => j >= 0)
    if (!chocan.length) return e
    const ajenos = new Set(chocan.flatMap(j => listas[j]))
    const propio = listas[i].find(x => x !== e && !ajenos.has(x))
    return propio ? `${propio} · ${e}` : e
  })

  // Ultimo recurso: la posicion. Afecta al 4,74% de las pistas.
  const cuantas = {}
  for (const e of base) cuantas[e] = (cuantas[e] ?? 0) + 1
  return base.map((e, i) => (cuantas[e] > 1 ? `${e} · ${i + 1}` : e))
}
```

### Tarea 3: la lista de pistas

Es la pieza central del rediseño: lo que sustituye al `<select>`.

**Archivos:**

**Interfaces:**

- Produce: `listaDePistas(pistas, elegida) -> string` (HTML), exportada de
  `public/tarjeta.js` y con tests. La función es pura; el cableado de eventos
  vive en `vista-sortear.js`.

- [ ] **Paso 1: los tests de `listaDePistas`**

Cubre: que agrupa por instrumento con su cuenta; que marca la elegida; que las
que no califican llevan `fuera del filtro`; que escapa el nombre del catálogo
(prueba con `<img onerror=...>`); y que **con una sola pista devuelve cadena
vacía** — no se dibuja lista ni cabecera.

- [ ] **Paso 2: rojo, luego implementar**

Agrupación: por familia de instrumento, no por el string exacto.
`Acoustic Guitar (steel)` y `Acoustic Guitar (nylon)` son el mismo grupo
(`ACÚSTICA`). Sugerido: `ACÚSTICA`, `DISTORSIÓN`, `LIMPIA`, `OTRAS`.

Cada fila lleva: posición (1..N), la etiqueta de la Tarea 1, el instrumento, la
afinación, el modelo de amplificador de **esa** pista, y su dificultad. El
`title` del elemento lleva el **nombre crudo completo**.

**`tuning: null` significa afinación estándar**, no desconocida: muestra
`E estándar`.

- [ ] **Paso 3: la selección por defecto**

La pista que viene elegida es `song.pistas[song.pistaPorDefecto]` — **la más
vista de las que cumplen el filtro**. Agrupar por instrumento cambia el orden
visual, **no** cuál viene elegida. En *Fade to Black* la elegida es el Lead de
Kirk (2.984.809 vistas), no el intro acústico, aunque el acústico se dibuje
arriba. Esto es una invariante de la spec §5.1: no la "arregles".

- [ ] **Paso 4: scroll sólo cuando hace falta**

`max-height` en la lista a partir de 7 filas, con `overflow-y: auto`. Afecta a
104 canciones de 9.788 (1,1%). Para el 98,9% restante no hay scroll interno.

- [ ] **Paso 5: cambiar de pista no pierde estado**

Al cambiar de pista se redibujan dificultad, afinación y el panel del ampli —
**sin pedir nada al servidor**: el objeto ya trae el tono de cada pista. Y hay
que conservar dos cosas que hoy ya se conservan: **el panel del ampli abierto y
un video sonando**. Se arregló en la rama anterior; no lo reintroduzcas.

- [ ] **Paso 6: verificar a mano** con una canción de 6 pistas (`Fade to Black`),
      una de 2-3 (el caso común, 61,3%) y una de 1 sola (19,4%, sin lista).
