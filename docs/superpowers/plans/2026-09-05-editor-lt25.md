# Editor completo del Mustang LT25 — plan de implementación

> **Para agentes:** SUB-SKILL REQUERIDA: usar superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans para implementar tarea por tarea. Los pasos usan casillas (`- [ ]`) para seguimiento.

**Goal:** Que la app controle el amplificador completo — modelo, las cuatro ranuras de efectos y todas las perillas de cada unidad — desde una vista propia, escribiendo en vivo.

**Architecture:** El servidor no cambia. Un catálogo estático de 48 unidades describe qué hay y cómo se muestra; un módulo puro convierte entre el valor del cable y el de pantalla; `fender-protocolo.js` suma dos mensajes; `ampli-usb.js` suma dos operaciones; un despachador serializa las escrituras del arrastre; y una vista nueva se genera del catálogo.

**Tech Stack:** Node 25 (`node:test`), ESM, HTML/CSS/JS a mano, WebHID, protobuf escrito a mano.

**Spec:** `docs/superpowers/specs/2026-09-05-editor-lt25-design.md`

## Global Constraints

- **Node ≥ 24. Cero dependencias npm.** Sin paso de build.
- **ESM**: `import`, nunca `require`.
- **Tests con `node:test`** y `node:assert/strict`, corridos con `npm test` (que es `node --test test/*.test.js`; un directorio pelado falla en Node 25).
- **Ningún test toca la red ni el hardware.** Lo puro se prueba con bytes y datos capturados; el ciclo WebHID y el DOM se verifican a mano.
- **Idioma**: interfaz, mensajes y comentarios en español. El vocabulario externo no se traduce: ranuras (`amp`, `stomp`, `mod`, `delay`, `reverb`), nombres de parámetro (`gain`, `treb`, `bass`, `time`, `feedback`…) y los `FenderId`.
- **Nunca declarar éxito sin confirmación del equipo.** El amplificador ignora en silencio lo que no entiende.
- **Un commit por tarea**, con la suite pasando.
- **La suite parte en 140 tests.** Cada tarea declara CUÁNTOS agrega, no a qué número llega: el orden de ejecución puede cambiar y un total absoluto se vuelve falso. Las tareas de DOM y WebHID no agregan ninguno.
- **Prohibido inventar un número de pantalla.** Si no se sabe convertir, se muestra el valor crudo.

### Task 1: Medir las curvas contra el amplificador

**Esta tarea la ejecuta el humano con el equipo enchufado.** Bloquea a la Task 2: sin esto no se puede convertir un valor a pantalla sin inventarlo.

**Files:**
- Create: `docs/lt25-curvas.md`

**Interfaces:**
- Produces: para cada curva usada por el catálogo, una tabla de pares `[cable, pantalla]` medidos, que la Task 2 interpola.

**Contexto.** El catálogo declara por parámetro una curva del valor en el cable (`taper`) y otra de la escala de pantalla (`remap.taper`). En 122 controles continuos coinciden, y entonces la relación cable ↔ pantalla es lineal entre sus extremos. En 34 **no** coinciden, siempre con el mismo patrón: `t20r`/`t20ri`, `t30`/`t30i`, `t10`/`t10i`. Los 34 incluyen el `volume` de los veinte amplificadores.

Hipótesis a contrastar, no a asumir: `tXX` sería una potencia con exponente `k = ln(XX/100) / ln(0.5)`, de modo que a mitad de recorrido la salida vale XX%. `t50` daría `k = 1`, o sea lineal.

```js
/* ---------------------------------------------------------------------------
   Lógica pura sobre el catálogo de unidades del Mustang LT25.

   Puro a propósito, igual que fender-protocolo.js: vive en public/ porque el
   navegador lo carga como módulo, pero test/ lo importa desde disco. Es donde
   está el riesgo real de esta función — un valor mal convertido llega al
   amplificador como un número plausible y equivocado, sin que nada avise.
   --------------------------------------------------------------------------- */

// El orden es el de la cadena de audio del equipo.
export const RANURAS = ['stomp', 'mod', 'amp', 'delay', 'reverb']

// La unidad que deja una ranura en bypass. El equipo la llama EMPTY.
export const VACIA = 'DUBS_Passthru'

const RANURAS_DE_EFECTO = ['stomp', 'mod', 'delay', 'reverb']

/* Pares [cable, pantalla] medidos contra el equipo (docs/lt25-curvas.md).
   Se interpola linealmente entre puntos consecutivos en vez de aplicar una
   fórmula: la fórmula es una hipótesis, los pares son lo que el equipo hizo.
   Una curva ausente se trata como recta entre sus extremos, que es lo correcto
   cuando la curva del cable y la de pantalla coinciden. */
const CURVAS = {
  // Una entrada por par de curvas que NO coinciden, con los pares medidos en la
  // Task 1 (docs/lt25-curvas.md). Formato, con el volume como ejemplo:
  //   't20r/t20ri': [[-60, 1], [-45, 3.2], [-30, 5.1], [-15, 7.4], [-6, 9.0], [0, 10]],
  // Que una curva no esté aquí no es un pendiente: es la respuesta correcta
  // cuando la curva del cable y la de pantalla son la misma, que es el caso de
  // 122 de los 156 controles continuos.
}

const interpolar = (pares, i, j, v) => {
  if (v <= pares[0][i]) return pares[0][j]
  for (let k = 1; k < pares.length; k++) {
    const [a, b] = [pares[k - 1], pares[k]]
    if (v <= b[i]) {
      const t = (v - a[i]) / (b[i] - a[i])
      return a[j] + t * (b[j] - a[j])
    }
  }
  return pares[pares.length - 1][j]
}

const acotar = (v, min, max) => Math.min(Math.max(v, min), max)

function conversores(p) {
  const dMin = p.remap?.min ?? p.min
  const dMax = p.remap?.max ?? p.max
  const pares = CURVAS[`${p.taper}/${p.remap?.taper}`]
  if (pares) return {
    aPantalla: c => interpolar(pares, 0, 1, acotar(c, p.min, p.max)),
    aCable: d => acotar(interpolar(pares, 1, 0, d), p.min, p.max),
  }
  // Sin curva medida: recta entre extremos. Es lo correcto cuando la curva del
  // cable y la de pantalla son la misma, que es el caso de 122 de los 156
  // controles continuos.
  const span = (p.max - p.min) || 1
  return {
    aPantalla: c => dMin + (acotar(c, p.min, p.max) - p.min) * (dMax - dMin) / span,
    aCable: d => acotar(p.min + (d - dMin) * span / ((dMax - dMin) || 1), p.min, p.max),
  }
}

// `%2.1f` -> 1 decimal; `%0.0f` -> 0. Sin formato declarado, un decimal.
const decimalesDe = fmt => {
  const m = /^%\d*\.(\d+)f$/.exec(fmt ?? '')
  return m ? Number(m[1]) : 1
}

function descriptor(p) {
  const base = { id: p.controlId, nombre: p.displayName ?? p.controlId, unidades: p.units ?? '' }
  if (p.controlType === 'list' || p.controlType === 'listBool') {
    const valores = p.listItems ?? []
    const nombres = p.remap?.listItems ?? valores
    return {
      ...base,
      tipo: p.controlType === 'listBool' ? 'interruptor' : 'lista',
      valores: valores.map((valor, i) => ({ valor, nombre: String(nombres[i] ?? valor) })),
    }
  }
  return {
    ...base,
    tipo: 'continuo',
    min: p.min, max: p.max,
    decimales: decimalesDe(p.remap?.format),
    ...conversores(p),
  }
}

export function crearCatalogo(unidades) {
  const porId = new Map(unidades.map(u => [u.FenderId, u]))
  const vacia = porId.get(VACIA)

  const entrada = u => ({ fenderId: u.FenderId, nombre: u.info?.displayName ?? u.FenderId })

  return {
    unidad: id => porId.get(id) ?? null,

    // Un FenderId que no está en el catálogo se muestra tal cual en vez de
    // desaparecer: si el equipo trae una unidad que no conocemos, el usuario
    // tiene que poder verla.
    nombre: id => porId.get(id)?.info?.displayName ?? id,

    deRanura(ranura) {
      const propias = unidades
        .filter(u => u.info?.subcategory === ranura)
        .map(entrada)
        .sort((a, b) => a.nombre.localeCompare(b.nombre, 'es'))
      // El ampli nunca queda vacío: la ranura siempre tiene un modelo.
      return RANURAS_DE_EFECTO.includes(ranura) && vacia ? [entrada(vacia), ...propias] : propias
    },

    parametrosDe(id) {
      return (porId.get(id)?.ui?.uiParameters ?? []).map(descriptor)
    },
  }
}
```

```js
/* ---------------------------------------------------------------------------
   Serializa las escrituras al amplificador y fusiona las que se atropellan.

   Arrastrar un control genera del orden de 60 eventos por segundo, y cada
   escritura cuesta dos mensajes mas su confirmacion (~120 ms medidos contra el
   equipo). Mandarlas todas es imposible, y mandarlas en paralelo es peor: el
   docblock de ponerParametro advierte que dos escrituras vivas sobre la misma
   perilla dejan que la correlacion de ACK resuelva la equivocada.

   Regla: una sola escritura en vuelo, y por cada clave se guarda unicamente el
   ultimo valor pendiente. Los intermedios de un arrastre se descartan; el
   ultimo siempre sale.
   --------------------------------------------------------------------------- */
export function crearDespachador(escribir) {
  const cola = new Map()      // clave -> ultimo valor pendiente
  const oyentes = []
  let corriendo = false

  async function vaciar() {
    if (corriendo) return
    corriendo = true
    try {
      while (cola.size) {
        // El Map conserva el orden de inserción: sale la clave que espera hace
        // más tiempo, así una perilla que se arrastra no deja a otra en ayunas.
        const [clave, valor] = cola.entries().next().value
        cola.delete(clave)
        let fallo = null
        try { await escribir(clave, valor) } catch (err) { fallo = err }
        for (const fn of oyentes) fn(clave, valor, fallo)
      }
    } finally {
      corriendo = false
    }
  }

  return {
    /* Encola un valor. Si ya habia uno pendiente para esa clave, lo reemplaza:
       el valor viejo de un arrastre no le sirve a nadie. */
    poner(clave, valor) {
      cola.set(clave, valor)
      return vaciar()
    },
    alTerminar(fn) { oyentes.push(fn) },
    enVuelo: () => corriendo || cola.size > 0,
  }
}
```

```js
const cat = JSON.parse(fs.readFileSync('dsp_units.json','utf8'))
const orig = unidades(await leerPreset())
const fallos = []
for (const u of cat) {
  const ranura = u.info?.subcategory
  if (!['amp','stomp','mod','delay','reverb'].includes(ranura)) continue
  await reemplazar(ranura, u.FenderId, `${ranura} <- ${u.info.displayName}`)

  if (puesto !== u.FenderId) fallos.push({ pedido: u.FenderId, quedo: puesto, nombre: u.info.displayName })
}
for (const [nodo, fid] of Object.entries(orig)) await reemplazar(nodo, fid, `restaurar ${nodo}`)
console.log(fallos.length ? fallos : 'las 45 unidades de ranura fueron aceptadas')
```
